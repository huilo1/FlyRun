# FlyRun

[English](README.md) · [GitHub](https://github.com/huilo1/FlyRun) · [Как внести вклад](CONTRIBUTING.md)

Основной сайт: https://flyrun.runningdog.org. Развёртывание и повторные публикации описаны в [DEPLOYMENT.md](DEPLOYMENT.md).

Браузерный эксперимент: реальный коннектом MaleCNS из Xenova/fruit-fly-simulation управляет агентом в случайной просторной комнате. Интерфейс на русском, WebGPU с автоматическим CPU fallback. Все вычисления и данные локальны после загрузки; API-ключ не нужен.

## Запуск

Node.js >=22.13, npm:

```sh
git clone https://github.com/huilo1/FlyRun.git
cd FlyRun
npm ci
npm run dev
```

Откройте адрес сервера и нажмите **Запустить мозг**. Первая загрузка читает около 76 МБ сжатых данных, проверяет SHA-256 графа и кеширует их в браузере. WebGPU требует localhost или HTTPS. Полная сеть использует несколько сотен МБ памяти. Реальная скорость зависит от устройства; физика идёт по модельному времени, не по FPS.

```sh
npm test
npm run test:brain   # реальный полный граф, CPU, около минуты
npm run test:walls   # регрессия прежнего режима с прямыми DN-входами
npm run test:sensory # полный граф: сенсорные ответы и отключение связей
npm run build
npm run test:gpu     # production Worker в отдельном headless Chrome с настоящим WebGPU
```

Проверка GPU по умолчанию использует Chrome из стандартного пути macOS. На другой системе задайте путь к исполняемому файлу через `FLYRUN_CHROME`; требуется аппаратный WebGPU. Для статического запуска после сборки: `python3 -m http.server 8000 --bind 127.0.0.1 --directory dist/client`, затем откройте `http://localhost:8000`.

## Сенсомоторный цикл

1. `lib/world.mjs`: комната 100×68 условных мм, просторные проходы, стены, опасные объекты и светящийся выход. Генератор проверяет доступность выхода с запасом радиуса 2,5 мм. Поиск пути используется только для проверки геометрии.
2. Пятнадцать лучей, радиус 24 мм, различают тип и близость препятствий. Свет выхода воспринимается только в поле зрения, на расстоянии до 43,2 мм и без перекрытия препятствиями. Контакт — отдельный сигнал.
3. `lib/sensor-encoder.mjs`: **по умолчанию только зрительные входы, без прямой стимуляции двигательных нейронов**. LC9 получает симметричный искусственный фон 180 Гц; LC10a — локально видимый светящийся объект; LC16 — близость и увеличение близости преград; LC4 — изменение близости опасной поверхности с затуханием постоянного сигнала за несколько постоянных времени по 250 мс. Сторона сигнала соответствует стороне объекта, готовая команда поворота не подаётся. Численные соответствия условны; это не модель сетчатки. Выключение обратной связи оставляет только фон LC9. Прежние DNp09 / DNa02 / MDN доступны как отдельный контрольный режим. В нём контакт вперёд запускает ограниченный импульс MDN до 300 мс, контакт назад его отменяет.
4. `lib/neural/worker.js`: исходная импульсная LIF-сеть Xenova, 166 700 узлов, 25 582 938 направленных связей. Веса не переобучаются. Шаг нейрона 0,1 мс, сенсорное обновление и считывание каждые 10 мс.
5. Движение считывается из спайков DNp09/DNg100/DNg97, DNa02/DNa11/DNg13, MDN и DNp01. Декодер не видит датчики, карту или выход. DNp01 усиливает ходьбу; полёт не реализован. Коллизии блокируют перемещение без автоматического поворота. Поворот учитывает малую разность активности сторон без прежнего отсечения ниже 15 Гц. Панель показывает фактическую скорость перемещения, а направление контакта определяется командой скорости.
6. Новое положение изменяет следующий сенсорный вход.

В основном сенсорном режиме зрительные входы и моторные выходы не пересекаются. Worker проверяет это при загрузке и на каждом шаге, а панель показывает число прямо стимулируемых моторных нейронов. Отключение связей после сброса даёт нулевой моторный ответ при продолжающейся активности зрительных клеток; при переключении во время движения остаётся краткий переходный процесс. В контрольном режиме с прямыми DN-входами движение возможно и без связей.

Устойчивая ходьба через LC9 и повороты через LC10a проверены на полном графе CPU; выход из первого застревания и отключение связей также проверены в настоящем WebGPU Chrome. Сырые результаты WebGPU доступны в `/neural/gpu-validation.json`. Надёжный обход препятствий **не установлен**: LC16 слабо активирует MDN, особенно на фоне LC9. Муха может застрять. Сеть необходима для движения в основном режиме, но это не доказывает биологическую достоверность. Протокол, результаты и ограничения: [SENSORY_EXPERIMENT.md](SENSORY_EXPERIMENT.md), машиночитаемый отчёт: `/neural/sensory-validation.json`.

## Воспроизводимость и ограничения

Seed определяет геометрию и входной исследовательский шум. CPU использует его также для Poisson-стимуляции; GPU сохраняет фиксированный seed=1 исходной модели, поэтому траектории между backend не обязаны совпадать. Повторение с одинаковыми настройками внутри одного backend воспроизводимо. Живые изменения параметров меняют траекторию.

Случайный поиск может не завершиться. Никакой скрытый планировщик, телепортация или заранее вычисленный маршрут мухе не помогают. Сенсорный адаптер, масштаб, двигательные коэффициенты и геометрия условны. Это не валидированная эмуляция поведения животного. Анатомическое облако отображает выборку реальных координат, а счётчик активности учитывает все нейроны.
